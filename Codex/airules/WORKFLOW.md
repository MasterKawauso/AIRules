# WORKFLOW — 分担・長期作業フロー

`AGENTS.md`の作業開始ゲート該当、実装・修正、タスク分割・並列実装時に適用。コード・ファイルを変更しない調査、質問への回答、説明、設計、レビュー・差分確認と、同書の全条件を依頼文だけで確認できる軽微な実装は対象外。各実装は`AGENTS.md`に従う。

## 選択ゲート

1. 次の順に、担当AI・モデル・思考深度の有効な選択を探す
   - 現在のユーザー依頼で3項目が指定済み、または「現在のAIで確認なしに続行」等の明示がある
   - 同じ会話・同じ作業単位で、推奨案への通常の承認（「はい」「よい」「それで」「進めて」等）、現在モデルでの続行指示、または3項目の回答が済んでいる。定型文やラベル付き形式を要求しない
   - `PLAN.md`、次に`SESSION.md`に、ユーザー承認済みの次の1行がある
     `AIRULES_WORKFLOW_SELECTION: owner=Codex; model=gpt-5.6-sol; thinking=medium; scope=<作業単位>`
   AIが未承認の値をこの行へ書いて確認を代替してはならない。3項目の一部だけ、別作業の記録、scopeが現在作業と一致しない記録は無効。機械ゲートは、現在の依頼にscope文字列があるか、`PLAN.md`/`SESSION.md`の作業を再開すると明記された場合だけ記録を採用する
2. 選択の有効範囲は、同じ作業単位の設計・実装・修正・検証・レビューまでの一連の流れとする。工程が移るたびに再質問せず、同じ会話の追補・再試行でも再質問しない。新しい会話、またはユーザーが「別件」「新しい依頼」等で別作業を開始した時点で失効する
3. 未選択なら`AGENTS.md`の客観条件を別々に判定する。軽微な実装は、対象ファイル、局所変更の種類、単一箇所、禁止境界に触れないことを依頼文から確認できる場合だけ認め、「軽微」「簡単」等の自己申告だけでは認めない。「設計を伴う」は既存責務・依存方向・状態遷移・公開境界のいずれかを決める変更、「複数責務」は同書の分類を2つ以上変更する作業とする。どちらか一方でも対象であり、両方を満たす必要はない。「品質・費用・時間が実質的に変わる」は実装をSub Agent・複数AIへ委譲・並列化する、または広範囲・高リスクの実変更でモデル/思考深度の選択が検証量や失敗影響を変える場合とする
4. 対象なら、事実確認の読取調査だけを許可し、現在の担当・モデル・思考深度設定、推奨する担当・モデル・思考深度、Worker/Sub Agentの使用有無（使う場合はモデル）、品質・費用・時間の差を一度に示して回答を待つ。Codexで実行中設定を取得不能なら`config.toml`の既定値と明記する。既定担当は推奨根拠であり省略根拠ではない

Claude CodeとCodexでは`workflow_gate.ps1`が会話・作業単位の選択状態を保持する。選択待ちは現在の実装・修正・実装委譲依頼だけで強制し、途中の調査・質問回答・説明・設計・レビュー・雑談では休止して応答や読取ツールを妨げず、実変更へ戻った時だけ再開する。`UserPromptSubmit`は依頼分類、`PreToolUse`は未選択時の変更・実装委譲停止、`Stop`は推奨案を出さず終了する経路の差戻しを担う。壊れたpayloadや旧schemaの状態、状態保存不能は通常会話を失わせないためfail open、未選択と判定済みの変更系ツールはfail closedとする。読取専用Agent・明確な読取コマンド・変更操作を含まないNode REPLコードは通す。

## 基本フロー

1. 要件→設計→分割→実装→成果物レビュー→統合→統合レビュー→完了の順に進む。整理済みの`PLAN.md`は要件、設計文書は設計工程を兼ね、不足部分だけ補う
2. 独立性と統合点が明確な作業だけ1〜5 Workerへ分割する。各成果物は1回レビューし、問題箇所だけ修正・再確認する。Codexは成果物別レビューを統合レビューへまとめてよい
3. 統合レビューは統合差分と接続点だけを対象にする。Public API/データ構造、破壊的変更、セキュリティ、広範囲・高リスク変更はCodex↔Claudeで相互レビューし、それ以外は単独レビューでよい。往復は2回まで
4. 相互レビューは変更差分、仕様、未決事項だけを渡す。Claude→Codexは`codex:rescue`、Codex→Claudeは`Get-Command claude`確認後`claude -p "<レビュー依頼>"`。必須レビューが利用不能なら停止してユーザーへ依頼する

Sub Agent起動時は選択済みでもmodelを省略しない。Claude Codeでは`require_agent_model.ps1`がmodel未指定を拒否する。`Explore`等の読取専用Sub Agentは対象外。これは親AIの選択ゲートとは独立した費用事故防止線である。

Codexでは親のモデル・思考深度を処理中に変更できない。ユーザー選択が親の実行中設定と異なる場合は、対応モデルを指定したWorkerを原則起動し、Workerへ実装、親へ調査・統合・報告を割り当てる。利用可能なWorkerモデルに選択値がなければ勝手に近似モデルへ置換せず、現在モデルで続けるかユーザー側で切り替えるかを確認する。

## 役割

- Architect: 仕様・設計、分割、完了条件
- Worker: 担当範囲だけ実装。範囲外の仕様・設計変更や大規模リファクタは禁止し、不明点を報告
- Reviewer: 担当差分を`REVIEW.md`で確認し、実害のある問題だけ示す
- Integrator: 統合、接続漏れ・競合・仕様差異、必要最小限の統合修正、最終レビュー

## 長い会話の引継ぎ

残り文脈では安全な完了が難しい、会話の要約・圧縮が発生した、または長い調査出力で重要情報が埋もれ始めた場合に限り、作業の安全な区切りでプロジェクト直下の`SESSION.md`を新規作成または更新する。進行中の不可分な変更・復旧操作は区切りまで終える。

`SESSION.md`には次だけを簡潔に記す。

- 目的・完了条件
- 完了した成果と重要な決定
- 現在の状態、変更ファイル、検証結果
- 残作業を再開順に列挙し、次に実行する確認・コマンドを明記
- 未決事項、阻害要因、注意点

会話全文、既存`PLAN.md`/`PROGRESS.md`の転載、秘密情報、不要な試行履歴は含めない。保存後、ユーザーへ「新しいセッションで`SESSION.md`を読んで続行」と切替を促す。新セッションは同ファイルを1回読み、実際の差分・状態を確認してから再開する。完了済み内容を再実行しない。恒久的な成果は`PROGRESS.md`、一時的な引継ぎだけを`SESSION.md`に置く。
