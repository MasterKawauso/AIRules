# WORKFLOW — 分担・長期作業フロー

`AGENTS.md`の作業開始ゲートに該当するコード実装・修正、分担・並列実装時に適用。同書が除外する文書編集等の非コード変更と軽微実装は対象外。各実装も同書に従う。

## 選択ゲート

1. 担当AI・モデル・思考深度の選択を次の順で探す
   - 現在の依頼で3項目を指定済み、または現在のAIで確認なしに続行する明示
   - 同じ会話・作業で、番号付き候補への回答、推奨への通常の承認（「はい」「進めて」等）、現在モデルでの続行指示、または3項目への回答済み
   - `PLAN.md`、次に`SESSION.md`にあるユーザー承認済みの次の行
     `AIRULES_WORKFLOW_SELECTION: owner=Codex; model=gpt-5.6-sol; thinking=medium; scope=<作業単位>`
   定型回答は要求しない。AIが未承認値を書いて代用してはならず、一部欠落・別作業・scope不一致は無効。機械ゲートは依頼にscopeがあるか、記録した作業の再開が明示された場合だけ採用する
2. 選択は同じ作業の設計からレビューまで有効で、工程移行・追補・再試行では再確認しない。新しい会話または明示された別作業で失効する
3. 未選択なら`AGENTS.md`の各条件を独立に判定する。軽微実装は対象、局所変更の種類、単一箇所、禁止境界外を依頼文だけで確認できる場合に限り、自己申告では認めない。設計変更は責務・依存方向・状態遷移・公開境界の決定、複数責務は同書の分類2つ以上の変更を指す。委譲・並列化または広範囲・高リスク変更で選択が検証量や失敗影響を変える場合も対象
4. 対象なら読取調査だけ行い、現在設定と、推奨を1番にした2〜3候補を示して待つ。各候補に担当・モデル・思考深度、Worker使用有無と使用設定、品質・費用・時間差を含め、「推奨」か番号だけで回答可能にする。現在設定は、そのCodex自身の実行環境がセッションへ明示した実行中値から取得する。初回取得に失敗した場合は、表示直前に同じ実行環境のセッション情報から1回取り直す。親の申告、Worker起動時の指定値、`config.toml`等の設定ファイル、過去の会話は現在値の根拠にしない。再取得しても取得不能な項目だけ「取得不能」と示し、既定値や推測値で補わない。既定担当は省略理由にならない

`workflow_gate.ps1`は会話・作業ごとの選択状態を保持する。選択待ちはコード実装・修正・実装委譲時だけ強制し、非コード作業中は休止、コード変更へ戻ると再開する。依頼分類、未選択時の変更・委譲停止、候補未提示での終了差戻しを各Hookが担う。壊れた入力・旧状態・保存不能はfail open、未選択と確定したコード変更はfail closed。読取専用Agent・コマンド・Node REPLは通す。

## 基本フロー

1. 要件→設計→分割→実装→成果物レビュー→統合→統合レビュー→完了。整理済みの`PLAN.md`は要件、設計文書は設計を兼ね、不足工程だけ補う
2. 独立性と統合点が明確な作業だけ1〜5 Workerへ分割する。成果物を1回レビューし、問題箇所だけ修正・再確認する。Codexは成果物別レビューを統合レビューへまとめてよい
3. 統合レビューは統合差分と接続点に限定する。Public API・データ構造、破壊的、セキュリティ、広範囲・高リスク変更はCodex↔Claudeで相互レビューし、往復2回まで。その他は単独でよい
4. 相互レビューには差分・仕様・未決事項だけ渡す。Claude→Codexは`codex:rescue`、Codex→Claudeは`Get-Command claude`確認後`claude -p "<レビュー依頼>"`。必須時に利用不能なら停止してユーザーへ依頼する

## コンテキストと再試行

- Sub Agentは会話履歴なし、または未文書化の決定に必要な直近turnだけを既定とし、全履歴は複数の未文書化判断が不可欠な場合だけ渡す。目的・完了条件・対象範囲・必要な仕様とファイル・未決事項を短い作業パケットで渡すが、要約で対象コード・差分・必要な依存先の直接確認を代替しない
- 予算・文脈上限等で成果が返らなければ同じ範囲・条件で再実行せず、責務・機能・リスク別に縮小する。得られた結果と確認済み範囲は再利用し、未確認範囲と接続点だけを続ける
- 検索は対象・語句・ファイル種別を絞る。ビルド・テストの全ログは必要ならファイルに保持し、会話には成否・件数・最初の根本エラーと関連箇所を取り込む。独立した後続エラーや警告が疑われる場合だけ追加確認し、巨大な検索結果・全ログ・全diffを反復して会話へ入れない
- 確認済みの仕様・設計・差分は、内容または判断前提が変わらない限り再読しない。更新時は変更差分と影響先を確認し、要約や記録に疑義があれば原文へ戻る。削減対象は重複情報と成果のない再試行であり、一次情報・影響範囲・高リスク変更に必要な検証は省かない

Sub Agentは選択済みでもmodelを明示する。Claude Codeは未指定をHookで拒否するが、読取専用の`Explore`等は対象外。

Codexは処理中に親のモデル・思考深度を変更できない。選択値が親と異なる場合、同値を明示したWorkerへ実装、親へ調査・統合・報告を割り当てる。親が切り替わった扱いで実装してはならない。Workerで利用不能なら近似値にせず、現在設定の継続かユーザー側の切替を確認する。

Workerも自分の現在モデルを表示するときは、自身の実行環境が明示した値を取得し、初回に得られなければ表示直前に1回取り直す。親のモデル、起動要求の`model`、`config.toml`の値を、自身で実行中と確認できたモデルとして扱わない。

## 役割

- Architect: 仕様・設計、分割、完了条件
- Worker: 担当内だけ実装。範囲外の設計変更・大規模リファクタをせず、不明点を報告
- Reviewer: `REVIEW.md`に従い実害のある問題だけ示す
- Integrator: 統合、接続漏れ・競合・仕様差異、最小限の統合修正、最終レビュー

## 長い会話の引継ぎ

残り文脈で安全な完了が難しい、要約・圧縮が発生した、または重要情報が埋もれ始めた場合だけ、安全な区切りで直下の`SESSION.md`を作成・更新する。不可分な変更・復旧は区切りまで終える。

目的・完了条件、成果・決定、現在状態・変更ファイル・検証結果、再開順の残作業と次の確認・コマンド、未決事項・阻害要因・注意点だけを簡潔に記す。会話全文、既存文書の転載、秘密情報、不要な試行履歴は含めない。

保存後は新セッションで同ファイルを1回読み、実差分・状態を確認して続けるよう促す。完了済み内容は再実行しない。恒久成果は`PROGRESS.md`、一時引継ぎだけを`SESSION.md`に置く。
